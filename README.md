# Stay Property · сервис гостя

Рабочее локальное демо гостевого справочника и админки отдела аренды. Создано по согласованному визуальному макету: светлый фон, оранжевые акценты, фотографии, крупные мобильные кнопки.

## Запуск

Нужен Node.js 24 (проверено на 24.14.1).

```powershell
npm.cmd install
npm.cmd run dev
```

- Гость: http://localhost:3000/g/demo
- Админка: http://localhost:3000/admin
- Демо-логин: `admin`
- Демо-пароль: `StayDemo2026!`

По умолчанию сервер слушает только `127.0.0.1`. Используйте один адрес (localhost или 127.0.0.1) для гостя и админки, чтобы браузер не разделял cookie. При первом запуске создаётся `data/store.json`. Изменения сохраняются на диске, а не в localStorage. Для завершения обычного запуска нажмите Ctrl+C в терминале.

## Что работает

- Страница отдельной квартиры по QR/ссылке `/g/<token>`; у новых квартир случайный постоянный токен.
- Wi-Fi и копирование пароля; адрес, маршрут в картах, адрес на турецком для таксиста.
- Персональный менеджер по аренде: фото, имя и WhatsApp на главной и в разделе помощи. Контакт управляющего — для вопросов по комплексу. Кнопки связи появляются после указания номеров.
- Инструкции, правила комплекса, инфраструктура, выезд.
- Места рядом с категориями, описанием и ссылками на маршрут.
- Баннер Stay Property и форма персональной подборки недвижимости. В разделе покупки нет карточек менеджеров, телефонов и WhatsApp: обращения проходят через форму и учитываются в админке.
- Отдельные обращения по проживанию.
- Сохранение заявок, источник квартиры/комплекса/района, имя назначенного ответственного и версия согласия.
- Админка: обзор, CRUD квартир/комплексов/контактов/мест, баннер, заявки, статусы, CSV, удаление обращения, QR SVG и печатная карточка.
- «Гости и заезды»: персональный менеджер для каждого гостя, даты проживания, отдельная постоянная ссылка и QR. Заявки по такой ссылке сохраняют источник заезда и имя его менеджера.
- Серверная очередь Telegram с подтверждением результата, автоматическими повторами и ручной повторной отправкой.
- Русский и английский интерфейс гостя. Автоматически подготовленные места и шаблоны содержат RU/EN; произвольный ручной контент пока одноязычный.

## Telegram

Скопируйте `.env.example` в `.env`. Файл `.env` исключён из Git. Создайте бота через @BotFather, добавьте в рабочую группу с правом писать либо откройте личный чат с ботом и нажмите Start. Укажите:

```dotenv
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Перезапустите сервер. Токен хранится только на сервере и не появляется в API админки. Доставка использует [Telegram Bot API sendMessage](https://core.telegram.org/bots/api#sendmessage). Без настроек заявки остаются на диске со статусом «Telegram не подключён». После подключения ранее сохранённые неотправленные заявки тоже попадут в очередь. Реальная доставка не проверена: пользователь ещё не предоставил настройки бота и чата. Модуль протестирован с имитацией ответов Telegram, без внешней отправки.

Повторы отправки после неопределённого сетевого сбоя могут создать дубликат Telegram-сообщения. В каждом сообщении есть постоянный ID заявки. CRM пока не подключена.

## QR на телефоне

QR использует `PUBLIC_BASE_URL` из `.env`. `localhost` на телефоне означает сам телефон. Для демонстрации вне компьютера нужен доступный домен или локальный сетевой адрес. Для LAN задайте `HOST=0.0.0.0`, уникальный `ADMIN_PASSWORD` и `PUBLIC_BASE_URL=http://<IP-компьютера>:3000`, согласовав сетевой доступ. Публичный запуск должен использовать HTTPS. При смене базового домена QR надо перепечатать; правки Wi-Fi, контактов и описаний не меняют токен квартиры.

Общий QR квартиры показывает её базового менеджера. Чтобы каждый клиент видел именно своего менеджера, создайте карточку в «Гости и заезды», назначьте сотрудника и передайте клиенту персональную ссылку или QR этого заезда. Одна общая ссылка без идентификации не может различать разных клиентов. Изменение менеджера заезда не меняет персональную ссылку. Даты пока справочные и не закрывают доступ автоматически.

## Проверки

```powershell
npm.cmd run check
npm.cmd test
```

Интеграционные тесты используют изолированную временную папку и не меняют рабочую базу. Проверяют доступ, CSRF, валидацию, сохранение заявок, изменения данных, постоянство токена, QR, связи между сущностями и обработку результатов Telegram.

## Ограничения демо и развитие

Демо содержит примерную квартиру, фотографии и поисковые ссылки на места; это не подтверждённые адреса ближайших учреждений. Реальные телефоны не выдуманы — задайте их в «Контактах». Фотографии Unsplash сохранены локально в `public/assets/` и используются только как иллюстрации, включая условный портрет персонального менеджера.

Перед полноценным запуском: утверждённая политика обработки данных, реальные данные объектов и мест, роли сотрудников, индивидуальные учётные записи, база данных и резервные копии, отзыв/ротация гостевых ссылок, журнал изменений, полный перевод контента, аналитика открытий и кликов, загрузка фото, CRM. Админка уже требует пароль, использует HttpOnly cookie, CSRF-токен и ограничение частоты запросов; известный демо-пароль подходит только для локальной демонстрации.

Техническое продолжение для ИИ: `AI_HANDOFF.md`.


## Автозаполнение: места и инструкции

Откройте «Автозаполнение» в админке, выберите комплекс и найдите его адрес. Выберите правильную точку: общий адрес района может вернуть соседний объект. Можно вставить координаты или полную ссылку карты с координатами; короткие ссылки не разворачиваются. Выберите радиус 500–5000 м и нажмите «Найти места».

Поиск обращается к OpenStreetMap через Photon, по каждой из семи категорий: супермаркет, базар, аптека, больница, пляж, кафе, ресторан. До двух результатов на категорию, расстояния по прямой. Отсутствующие категории и часы работы обозначаются явно. Получение данных не означает проверку работы заведения. Подборка сначала сохраняется в черновик; отметьте нужные места, при необходимости измените описания RU/EN и опубликуйте. Места появляются у всех квартир комплекса. Повторная публикация не создаёт дублей с тем же OSM ID и не перезаписывает ручные правки.

Источники: [Photon API](https://github.com/komoot/photon/blob/master/docs/api-v1.md), [OpenStreetMap / ODbL](https://www.openstreetmap.org/copyright). Адреса кешируются на 7 дней, подборки на 24 часа в приватном `data/assistant-cache.json`. Запросы последовательно ограничены по частоте. Для нагрузки полноценного сервиса нужен собственный или выделенный провайдер: публичные серверы не дают гарантии доступности. `GEOCODER_URL` и `PHOTON_REVERSE_URL` настраиваются в окружении. При указании `OVERPASS_URL` поиск мест использует этот Overpass вместо Photon. Публичные Overpass во время проверки оказались недоступны; рабочий путь демо — Photon.

ИИ необязателен: карты и шаблоны работают без него. Для кнопки «Улучшить описания с ИИ» задайте `AI_GATEWAY_API_KEY` и `AI_GATEWAY_MODEL` в локальном `.env`, затем перезапустите сервер. Модель выбирается из [каталога AI Gateway](https://ai-gateway.vercel.sh/v1/models), например поддерживаемый на момент разработки `openai/gpt-5.4-mini`. Запросы к модели оплачиваются по условиям провайдера. Ключ браузеру не передаётся. ИИ получает только названия и категории мест, готовит краткие RU/EN описания; координаты, ссылки и часы остаются из карт. Результат требует просмотра администратором. Живой вызов ИИ без настроенного ключа не выполнялся.

Шаблоны инструкций формируются без ИИ. Укажите время выезда/тишины при необходимости, проверьте двуязычный текст, оборудование и правила. Примените к одной квартире или комплексу. По умолчанию заполняются только пустые поля; замена существующих — отдельная опция. Для всего комплекса сохраняется также шаблон новых квартир. При ручном изменении русского поля его старый английский перевод удаляется, чтобы не показывать устаревшую инструкцию.

Для изолированной браузерной проверки: `node tests/browser-qa-server.mjs`, адрес `http://127.0.0.1:3001/admin`, логин `admin`, пароль `BrowserTestOnly!`. Сервер создаёт отдельную папку `data/browser-qa-*`, не читает `.env` и отключает Telegram/ИИ. Не используйте эти данные для реальных клиентов.

На 08.10.2026: 3 демонстрационных комплекса в Оба, 8 квартир, 3 персональных менеджера и 2 управляющих, 9 заездов, 12 примеров обращений, 8 мест района для каждого комплекса. Гости/заявки вымышлены, контакты маскированы. Расписания инфраструктуры — условия демо-объектов. Источники реальных заведений указаны в карточках, расстояния до вымышленных домов не заявляются.

Повторное наполнение: остановите сервер, выполните `node scripts/populate-demo.mjs` для просмотра, затем `node scripts/populate-demo.mjs --apply` для записи с резервной копией. Существующие ссылки и Wi-Fi сохраняются. Не запускайте запись параллельно работающему серверу.

По просьбе пользователя синтетические заявки с `isDemo` тоже отправляются в Telegram с пометкой «ДЕМО». Новые заявки из форм используют ту же очередь. Бот подключён к личному чату пользователя. Протокол финальной проверки: `VERIFICATION.md`.
