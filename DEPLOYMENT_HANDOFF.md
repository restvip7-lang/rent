# Передача ИИ: публикация демо Stay Property и QR

Актуально на 08.10.2026. Задача следующего ИИ — разместить проект через Git и Vercel, получить постоянную публичную HTTPS-ссылку и подготовить QR, по которому гость с телефона откроет работающий демо-сервис. Публикация в рамках этой передачи ещё не выполнена.

## Что прочитать и сохранить

- `README.md` — запуск и функции; `AI_HANDOFF.md` — история реализации; `VERIFICATION.md` — проверки. Более поздние записи отменяют старые ограничения демо-отправки.
- Проект: Node.js ESM, `server.mjs`, статический интерфейс в `public/`, зависимости в `package-lock.json`. Локально Node 24.14.1.
- Репозиторий Git уже существует. Сначала проверить status, remotes и текущие изменения. Не выполнять reset, не перезаписывать чужие изменения и не создавать репозиторий заново.
- Не публиковать `.env`, `data/`, резервные копии, токены, пароли и реальные персональные данные. Проверить staged diff и историю перед отправкой. В `.gitignore` есть `.env*`; при необходимости добавить исключение `!.env.example` для безопасного шаблона.
- Пользователь просил демо с админкой, персональным менеджером аренды, информацией о квартире и местах рядом, формами обращений и покупки, Telegram. CRM пока не подключать: доступа нет.
- На странице покупки оставить только форму, без прямых контактов продавца. Менеджер аренды назначается через админку; при отсутствии WhatsApp кнопка ведёт в форму обращения.

## Telegram: последнее состояние

Бот `@stayrent_bot` подключён к группе **«Rent заявки»**, ID `<chat id в Vercel env>`. Пользователь добавил бота и отправил `/start@stayrent_bot`. В локальном `.env` обновлён `TELEGRAM_CHAT_ID`; сервер перезапущен. Telegram подтвердил проверочное сообщение в группе (`message_id: 18`). Токен уже хранится в локальном `.env`: передать его в секреты окружения безопасным способом, не выводить в чат, логи или Git.

Все 12 ранее отправленных демонстрационных заявок доставлены в прежний личный чат. Их статусы `sent` сохранять; смена группы не должна автоматически пересылать их повторно. Новые заявки направляются в группу. Демо-отправка разрешена пользователем: `isDemo` помечает сообщение «ДЕМО», но не запрещает отправку. Не восстанавливать старый запрет. Живое прохождение новой формы в группу после переключения ещё не проверено; проверочное сообщение подтверждает только доступ бота к группе.

## Обязательные исправления перед Vercel

1. **Согласовать точку входа.** Сейчас `vercel.json` перенаправляет всё на `/api/index` и содержит настройку `api/index.mjs`, но такого файла нет. `server.mjs` экспортирует `server`, а вызов `listen` отключён при `VERCEL`. Выбрать один подход: поддерживаемый Vercel нативный Node HTTP server с корректным запуском либо настоящий обработчик API с адаптацией существующего сервера. Исправить конфигурацию целиком, проверить маршруты и включение `public/**`. Простая загрузка текущих файлов не завершает развёртывание.
2. **Постоянное хранилище.** Сейчас база — `data/store.json`, загружаемая в память; сохранение пишет файл. Это не надёжная общая база для нескольких экземпляров Functions. Перенести данные в постоянное хранилище, например Postgres; мигрировать чтение и запись, обеспечить согласованность конкурентных изменений. `/tmp` не использовать как базу заявок. Не перезаписывать всю базу устаревшим снимком из памяти.
3. **Авторизация и ограничения.** Проверить хранение сессий и CSRF между экземплярами и холодными стартами; использовать общее хранилище либо корректно подписанные сессии. Проверить secure-cookie, Origin за прокси, вход/выход, защиту админских API и ограничение частоты публичных форм. Локальные Map не обеспечивают общую защиту для нескольких экземпляров.
4. **Надёжная отправка Telegram.** Текущие `void drain()` и таймер процесса не гарантируют выполнение после ответа Functions. Сохранять заявку прежде отправки, использовать ожидаемую сервером отправку и надёжный механизм повторов либо постоянную очередь/outbox. Защитить захват заявки от двух работников; сохранять попытки, ошибки, `message_id`, статус. Не обещать строго однократную доставку при неопределённом исходе сетевого запроса. Учитывать лимиты Telegram и длину сообщения.
5. **Поиск мест.** Геопоиск делает последовательные внешние запросы; проверить время выполнения функции, отмену и таймауты. Черновики мест должны переживать перезапуск. Кеш `data/assistant-cache.json` перенести либо сделать необязательным; потеря кеша не должна удалять опубликованные данные. Поиск работает без AI-ключа. AI-описания опциональны, факты о местах модель не должна придумывать.

Актуальные официальные справки для выбора реализации: [Node.js runtime и HTTP server](https://vercel.com/docs/functions/runtimes/node-js), [ограничения Functions](https://vercel.com/docs/functions/limitations), [Cron](https://vercel.com/docs/cron-jobs), [защита развёртываний](https://vercel.com/docs/deployment-protection). Проверить актуальные требования платформы при выполнении.

## Окружение публикации

| Переменная | Значение / действие |
| --- | --- |
| `PUBLIC_BASE_URL` | Постоянный публичный HTTPS-домен демо без завершающего `/`; используется для QR и проверки Origin |
| `ADMIN_USER` | Выбранный логин администратора |
| `ADMIN_PASSWORD` | Новый уникальный пароль; стандартный локальный пароль не публиковать |
| `TELEGRAM_BOT_TOKEN` | Секрет из локального окружения, только на сервере |
| `TELEGRAM_CHAT_ID` | `<chat id в Vercel env>`, группа «Rent заявки» |
| Переменные БД/сессий/очереди | Добавить согласно выбранной реализации и описать их имена в README без секретных значений |
| `AI_GATEWAY_API_KEY`, `AI_GATEWAY_MODEL` | Необязательно; без них должны работать базовый сервис, поиск и шаблоны |
| `GEOCODER_URL`, `PHOTON_REVERSE_URL` | По умолчанию Photon, см. `.env.example` |
| `OVERPASS_URL` | Необязательно, только рабочий проверенный endpoint |

Не переносить локальные `HOST=127.0.0.1`, `PORT` и `PUBLIC_BASE_URL=http://localhost:3000` без адаптации к выбранному запуску. Не давать Preview окружению автоматически рассылать накопленные заявки в рабочую группу при каждом запуске тестов. Настроить Production явно; после изменения переменных выполнить нужное повторное развёртывание.

## Демо-данные и миграция

Локальная база содержит 3 комплекса, 8 квартир, 5 контактов, 9 заселений, 24 записи мест (8 разных мест для трёх комплексов) и 12 синтетических заявок. Фото и адреса квартир иллюстративные. Общая демо-ссылка — `/g/demo`. Есть персональные ссылки с токенами заселений: они определяют назначенного менеджера. Общий QR квартиры сам по себе не определяет конкретного гостя.

Варианты наполнения: защищённая однократная миграция локального снимка с сохранением токенов и статусов либо однократное создание данных из `seed.mjs` и `populateDemo` в `demo-data.mjs`. Свежий набор отличается наличием старого локального заселения; не обещать идентичные токены. Не коммитить текущий store ради переноса. Не запускать seed при каждом запросе, холодном старте или деплое. Повторная миграция не должна сбрасывать редактирование, QR-токены и статусы доставки. Локальный скрипт `scripts/populate-demo.mjs --apply` требует остановленного локального сервера; для облака нужен отдельный контролируемый процесс миграции.

## Публичная ссылка и QR для презентации

1. Получить постоянный production-домен Vercel или согласованный собственный домен. Выставить `PUBLIC_BASE_URL=https://<этот-домен>`.
2. Проверить гостевую ссылку `https://<этот-домен>/g/demo` без авторизации Vercel в приватном окне. Настройки Deployment Protection проверить явно: QR должен открываться у обычного гостя. Не включать секрет обхода защиты в QR. Админка сохраняет собственный вход по паролю.
3. В админке скачать QR квартиры или персонального заселения. Текущие API: `/api/admin/qr/:apartmentId` и `/api/admin/stay-qr/:stayId`; требуют авторизации. Они создают SVG со ссылкой `/g/<token>`.
4. Проверить декодированное содержимое QR: правильный HTTPS-домен, нужный токен, отсутствие localhost и временного preview-адреса. Смена Wi-Fi или менеджера не должна менять токен. При смене домена QR нужно обновить.
5. Сохранить готовую карточку для демонстрации: SVG и удобный печатный PNG или PDF, подпись «Гид гостя Stay Property», читаемый адрес, достаточные белые поля вокруг QR.
6. Проверить реальное сканирование камерой телефона через мобильный интернет. Если доступа к телефону нет, честно отметить эту ручную проверку как ожидающую пользователя.

## Финальная приёмка

- Выполнить `npm ci`, `npm run check`, `npm test`. На момент передачи 22 теста проходили; после адаптации добавить проверки постоянного хранения и облачных сценариев.
- Проверить `/g/demo`, персональную ссылку, `/admin`, статические ресурсы, перезагрузку вложенной ссылки, RU/EN и мобильную ширину.
- Проверить Wi-Fi, карту, места, назначение менеджера, отсутствие прямого продавца на странице покупки, обе формы и согласие.
- Отправить по одной явно тестовой заявке аренды и покупки через опубликованный интерфейс; проверить сохранение в админке и приход в «Rent заявки». Использовать синтетические контакты. Не сбрасывать статусы старых 12 заявок ради этой проверки.
- Проверить сохранность редактирования и заявок после нового экземпляра/повторного деплоя; конкурентную отправку, повторную попытку Telegram и отсутствие повторной отправки уже успешной заявки при обычном перезапуске.
- Проверить админскую авторизацию, запрет доступа к данным без входа, CSRF, отсутствие токена Telegram и секретов в клиентском JS/ответах/репозитории.
- Проверить поиск → черновик → публикацию → отображение у гостя; при сбое внешнего сервиса показать понятную ошибку и сохранить введённые данные.
